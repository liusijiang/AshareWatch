## 4. 详细实施步骤与工序排期 (Step-by-Step Execution Plan)

### 阶段一：通达信 TCP Socket 协议与各 HTTP 源测试网关搭建 (预计耗时：1.5 人天)
1. **通达信原生 TCP 客户端原型构建**：
   - 使用 Node.js 原生 `net.Socket` 实现通达信二进制握手与心跳协议；
   - 配置内置主站候选池（深圳电信 `119.147.212.81:7709`、武汉电信 `119.97.185.34:7709` 等），实现快速连接建立、自动断线重连与服务器延时测速；
   - 实现买卖五档快照包解析与 09:25 逐笔成交分笔解析。
2. **HTTP 抓取与转码中间件**：
   - 集成 `iconv-lite` 处理腾讯和新浪的 `GBK` 字符集，杜绝乱码；
   - 封装防盗链 Header 注入器（新浪携带 `Referer: https://finance.sina.com.cn`，天天基金携带 `Referer: https://fundf10.eastmoney.com/`）；
   - 封装雪球 Session 自动换取与 Cookie 托管器。

### 阶段二：自动化断言、数据质量与跨源比对引擎 (预计耗时：1 人天)
1. **跨源交叉一致性断言**：
   - 针对同一标的（如贵州茅台 `600519`），同时向**腾讯、新浪、通达信、东财**发起请求，对比四者返回的最新成交价、昨收价、买卖一档价格是否完全一致；
   - 记录各源的行情更新时间戳，量化对比各源的延迟优劣。
2. **数据完整性与边界断言**：
   - 验证东财 242 根分时时间戳递增与数值自洽性；
   - 验证东财历史前复权 K 线与未复权 K 线的除权除息跳空缺口；
   - 验证科创板/创业板标的在非交易时段读取 `f260~f264` 盘后字段时的容错机制（不得抛出未捕获异常）。

### 阶段三：前端交互式测试与可视化验证页面 (预计耗时：1.5 人天)
1. **全源健康度指示看板**：
   - 顶部以徽章即时展示 **通达信 TCP、腾讯、新浪、东财、雪球、天天基金** 6 大通道的即时连通状态与往返时延（RTT）；
2. **多源同屏交叉验证器 (Cross-Validation UI)**：
   - 用户输入任意股票代码（或快捷点击 66 只股票池），页面并行拉取各源数据，并在同屏卡片中对比各源的最新价、现手、买卖五档与耗时差异；
3. **通达信专有 TCP 诊断面板**：
   - 显示主站服务器列表、ping 延时排序、一键切换主站；
   - 展示 09:25 开盘集合竞价第一笔大单的撮合量与价格；
4. **66 只股票池全量覆盖率矩阵**：
   - 批量测试 `/DOC/stockpool.json` 中 66 只股票，生成体检表格，标红异常代码。

### 阶段四：极限频控与稳定性压力评估 (预计耗时：0.5 人天)
1. 分别对通达信 TCP、腾讯批量、新浪、东财进行阶梯压力测试（1 QPS $\to$ 3 QPS $\to$ 5 QPS $\to$ 10 QPS）；
2. 检验新浪与东财在连续高频请求下的 403 触发点；
3. 验证通达信 TCP 连接在连续高频查询下的抗压能力与连接保活特性；
4. 输出最终的生产调度推荐参数。

## 6. 风险控制与应急预案 (Risk Control)

| 风险情景 | 触发条件 | 规避与应急预案 |
| :--- | :--- | :--- |
| **HTTP 外部 IP 临时封禁 (403 错误)** | 新浪或东财短时间内请求并发过大 | 1. 测试工具默认单并发，两次请求间隔 $\ge 200\text{ms}$；<br>2. 遭遇 403 时自动触发 15 分钟熔断冷却并报警；<br>3. 自动切换至无 HTTP 反爬风控的通达信 TCP 节点验证。 |
| **通达信部分行情站连接超时** | 个别券商主站端口变动或临时维护 | 内置 4~6 个不同地域的电信/联通主站 IP，实现自动测速并优选延迟低于 40ms 的健康节点。 |
| **新浪接口缺少 Referer 导致 403** | 请求未伪造合法来源 | 服务端代理统一自动注入 `Referer: https://finance.sina.com.cn` 与合规 User-Agent。 |
| **GBK 中文编码跨平台解析乱码** | 腾讯与新浪返回 GBK 字节流 | 服务端统一采用 `iconv-lite` 对原始 ArrayBuffer 进行 `gbk` 解码后再转 UTF-8，前端诊断台内置中文字符检测逻辑。 |
