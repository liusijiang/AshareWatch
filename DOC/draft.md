## 1. 主流免费数据源综合对比与选型矩阵

| 数据源 | 核心协议 / 传输层 | 实时快照 | 历史分时(1分) | 历史K线(复权) | 集合竞价 | 盘后固定价格 | 实时推送能力 | 频率限制 / 反爬风控 | 综合推荐度 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **东方财富 (push2)** | HTTP/JSONP / SSE | ✅ 极佳 (毫秒级) | ✅ 完整 (支持多日) | ✅ 5/15/30/60分/日/周/月(前后复权) | ✅ 包含匹配/未匹配量 | ✅ 专属字段 (f260~f264) | ✅ 支持原生 SSE 流 | 单 IP 建议 $\le$ 10 QPS，超过易被封禁 30~60 分钟 | ⭐⭐⭐⭐⭐ (综合首选) |
| **腾讯财经 (gtimg)** | HTTP / 纯文本/JSON | ✅ 极佳 (约2秒级) | ✅ 当日逐分/五日分时 | ✅ 日/周/月/分时K线 (前复权/后复权) | ⚠️ 仅最终开盘价，无撮合明细 | ❌ 无专属分时 | ❌ 无公开推送，需高频轮询 | 宽松，支持超长批量拼接 (100+标的/次)，单 IP 可承载 20+ QPS | ⭐⭐⭐⭐⭐ (批量快照首选) |

| **新浪财经 (sinajs)** | HTTP / JS 纯文本 | ✅ 稳定 | ⚠️ 仅日内 | ✅ 日K | ⚠️ 仅最终价与盘口 | ❌ 不支持 | ❌ 仅限轮询 | 严格校验 `Referer`，高频易触发 403 临时熔断 | ⭐⭐⭐ (备用快照) |

## 2. 数据源一：东方财富 (Eastmoney push2/push2his) 协议规范

东方财富是目前国内开放接口中**数据结构最为完备、指标最为丰富**的数据源，返回标准 JSON 数据。

### 2.1 证券标识规范 (`secid`)
格式：`{市场代码}.{证券代码}`
* **上海证券交易所 (上证A股/科创板/上证ETF)**：市场代码为 `1`，例如：
  * `1.600519` (贵州茅台)
  * `1.688981` (中芯国际)
  * `1.510300` (沪深300ETF)
* **深圳证券交易所 (深证主板/创业板/深证ETF)**：市场代码为 `0`，例如：
  * `0.000001` (平安银行)
  * `0.300750` (宁德时代)
  * `0.159915` (创业板ETF)
* **北京证券交易所 (北交所)**：市场代码为 `0`，例如：
  * `0.835185` (贝特瑞)

---

### 2.2 实时行情与综合盘口快照接口
* **Endpoint**: `https://push2.eastmoney.com/api/qt/stock/get`
* **Method**: `GET`
* **Query 参数**:
  * `secid`: 证券标识，如 `1.600519`
  * `fields`: 请求字段集合，常见字段集：
    `f43,f44,f45,f46,f47,f48,f49,f50,f51,f52,f57,f58,f60,f84,f85,f86,f168,f169,f170,f260,f261,f262,f263,f264`
  * `ut`: 用户令牌标识（传固定字符串即可，如 `fa5fd1943c7b864ebece17f108a4f686`）
  * `invt`: `2`
  * `_`: 当前毫秒时间戳

#### 核心返回字段字典映射（按 `f` 编码）：
| 字段 Key | 字段含义 | 说明 |
| :--- | :--- | :--- |
| `f43` | 最新成交价 | 浮点数 |
| `f44` | 最高价 | 当日最高价 |
| `f45` | 最低价 | 当日最低价 |
| `f46` | 今开盘价 | 当日开盘价 |
| `f47` | 成交量 | 手 (100股/手) |
| `f48` | 成交额 | 元 |
| `f57` | 股票代码 | 6位证券代码 |
| `f58` | 股票名称 | 中文字符串 |
| `f60` | 昨收盘价 | 前一交易日收盘价 |
| `f84` / `f85` | 总股本 / 流通股本 | 股 |
| `f168` | 换手率 | 百分比 (%) |
| `f169` | 涨跌额 | 最新价 - 昨收 |
| `f170` | 涨跌幅 | 百分比 (%) |
| `f19` ~ `f28` | 买一至买五挂单价量 | Ask/Bid 1~5 档位 |
| `f260` | **盘后固定价格成交量** | 股 (科创板/创业板) |
| `f261` | **盘后固定价格成交额** | 元 (科创板/创业板) |
| `f262` | **盘后固定价格成交笔数** | 笔数 |
| `f263` | **盘后固定价格买入申报未成交量** | 挂单股数 |
| `f264` | **盘后固定价格卖出申报未成交量** | 挂单股数 |

### 2.3 当日分时与多日历史分时趋势接口
* **Endpoint**: `https://push2.eastmoney.com/api/qt/stock/trends2/get`
* **Method**: `GET`
* **Query 参数**:
  * `secid`: 如 `1.600519`
  * `fields1`: `f1,f2,f3,f4,f5,f6,f7,f8,f9,f10,f11,f12,f13`
  * `fields2`: `f51,f52,f53,f54,f55,f56,f57,f58`
  * `ndays`: 天数。`1` 表示当日分时（9:30~15:00 每分钟一个点，共 241 或 242 点）；`5` 表示近 5 个交易日连续分时。
  * `iscr`: 是否复权 (`0`: 不复权, `1`: 前复权)

#### 返回数据结构示例：
```json
{
  "data": {
    "code": "600519",
    "market": 1,
    "name": "贵州茅台",
    "prePrice": 1800.00,
    "trends": [
      "2026-09-25 09:30,1805.00,1805.00,1806.00,1802.00,1520,27436000,1804.21",
      "2026-09-25 09:31,1806.50,1807.00,1808.00,1805.50,980,17700500,1805.10"
    ]
  }
}
```

> **`trends` 数组单项逗号分隔格式说明**：  
> `[时间(YYYY-MM-DD HH:mm), 开盘价, 收盘价, 最高价, 最低价, 成交量(手), 成交额(元), 均价]`

### 2.4 历史多周期 K 线接口 (带除权/复权)
* **Endpoint**: `https://push2his.eastmoney.com/api/qt/stock/kline/get`
* **Method**: `GET`
* **Query 参数**:
  * `secid`: `1.600519`
  * `klt`: K 线周期代码
    * `1`: 1分钟 K 线
    * `5`: 5分钟 K 线
    * `15`: 15分钟 K 线
    * `30`: 30分钟 K 线
    * `60`: 60分钟 K 线
    * `101`: 日 K 线
    * `102`: 周 K 线
    * `103`: 月 K 线
  * `fqt`: 复权方式 (`0`: 不复权, `1`: 前复权 QFQ, `2`: 后复权 HFQ)
  * `beg`: 开始日期，格式 `YYYYMMDD` (如 `20200101`，传 `0` 表示最早)
  * `end`: 结束日期，格式 `YYYYMMDD` (如 `20260925`)
  * `lmt`: 获取最大根数 (通常可设 `1000` 或 `2000`)
  * `fields1`: `f1,f2,f3,f4,f5,f6`
  * `fields2`: `f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61`

#### 返回数据结构示例：
```json
{
  "data": {
    "code": "600519",
    "market": 1,
    "name": "贵州茅台",
    "klines": [
      "2026-09-24,1790.00,1800.00,1810.00,1785.00,32000,576000000,1.39,0.56,10.00,0.25",
      "2026-09-25,1805.00,1812.00,1818.00,1798.00,28500,515850000,1.11,0.67,12.00,0.23"
    ]
  }
}
```

> **`data.klines` 逗号分隔字段解析**：  
> `日期/时间, 开盘价, 收盘价, 最高价, 最低价, 成交量(手), 成交额(元), 振幅(%), 涨跌幅(%), 涨跌额, 换手率(%)`

## 3. 腾讯财经 (Tencent gtimg) 接口规范

腾讯财经以其**网络带宽冗余高、响应极快、支持批量查询**著称，数据源极其稳定，是构建后端高并发快照拉取的黄金方案。

### 3.1 证券标识规范
* 上交所：`sh` + 6位代码，如 `sh600519`
* 深交所：`sz` + 6位代码，如 `sz000001`
* 北交所：`bj` + 6位代码，如 `bj835185`

---

### 3.2 批量实时行情快照接口
* **Endpoint**: `https://qt.gtimg.cn/q={code_list}`
* **Method**: `GET`
* **URL 示例**: `https://qt.gtimg.cn/q=sh600519,sz000001,sh510300`
* **Header 要求**:
  * 编码：GBK (服务端请求需采用 `iconv-lite` 或 `TextDecoder('gbk')` 解码)
  * 限制：每次请求最多可拼接 **100 ~ 200 个标的**，极大节约网络 I/O。

#### 返回数据格式：
```text
v_sh600519="1~贵州茅台~600519~1800.00~1795.00~1798.00~15200~8200~7000~1799.90~12~1799.80~5~...~20260925150000~5.00~0.28~1810.00~1792.00~...";
```

#### 关键波浪线 (`~`) 下标索引字典：
| 索引位置 | 字段名称 | 单位/说明 |
| :--- | :--- | :--- |
| `1` | 证券名称 | 中文字符串 (GBK解码) |
| `2` | 证券代码 | 6位代码 |
| `3` | 当前最新价 | 元 (浮点数) |
| `4` | 昨收盘价 | 元 |
| `5` | 今开盘价 | 元 |
| `6` | 成交量 | 手 (100股/手) |
| `9` ~ `18` | 买一到买五价格与委买量 | 价格与股数按序交替 |
| `19` ~ `28` | 卖一到卖五价格与委卖量 | 价格与股数按序交替 |
| `29` | 最近逐笔成交明细 (最近一笔) | 格式: `时间/价格/成交量/性质` |
| `30` | 行情更新时间戳 | 格式: `YYYYMMDDHHmmss` |
| `31` | 涨跌额 | 最新价 - 昨收 |
| `32` | 涨跌幅 | 百分比 (%) |
| `33` | 最高价 | 元 |
| `34` | 最低价 | 元 |
| `37` | 总成交金额 | 万元 |
| `38` | 换手率 | 百分比 (%) |
| `44` | 流通市值 | 亿元 |
| `45` | 总市值 | 亿元 |

### 3.3 当日分时逐分明细接口
* **Endpoint**: `https://web.ifzq.gtimg.cn/appstock/app/minute/query`
* **Query 参数**: `code=sh600519`
* **返回格式**: JSON 格式。包含当日 09:30 ~ 15:00 所有逐分价格与累计成交量。

```json
{
  "code": 0,
  "msg": "",
  "data": {
    "sh600519": {
      "data": {
        "data": [
          "0930 1805.00 1200 2166000",
          "0931 1806.20 2300 4154000"
        ]
      }
    }
  }
}
```

> **单项字符串解析**：  
> `[时间HHmm, 当前价格, 累计成交量(手), 累计成交额(元)]`

### 3.4 腾讯历史复权 K 线接口
* **Endpoint**: `https://web.ifzq.gtimg.cn/appstock/app/fqkline/get`
* **Query 参数**: `param={code},{kline_type},{start_date},{end_date},{count},{fq_type}`
  * 示例：`param=sh600519,day,,,640,qfq`
  * `kline_type`: `day` (日K), `week` (周K), `month` (月K), `m5` (5分钟), `m15`, `m30`, `m60`
  * `fq_type`: `qfq` (前复权), `hfq` (后复权), 不填为不复权
  * `count`: 获取的最大根数 (如 `640`)

## 4. 通达信底层行情服务 (TCP 二进制协议 / pytdx)

对于需要在服务端实现**毫秒级高频快照拉取**、**海量标的批量并发查询**或**无惧 Web 反爬限制**的场景，通达信 L1 协议直连是金融工程界最成熟的非官方协议。

### 4.1 技术原理
* 通达信（TDX）金融终端通过长连接直接连接全国数十个券商开放部署的**行情主站网关**（默认端口 `7709`）。
* 该协议是基于二进制流的专有封包协议，数据不走 HTTP 协议栈，开销极小（TCP 帧无大量冗余 HTTP 标头）。
* 业界已有高度成熟的开源实现：`pytdx` (Python) 和相应的 Node.js/Go 重写库。

### 4.2 常用可用行情主站 IP 列表 (TCP:7709)
* 深圳电信主站：`119.147.212.81:7709`
* 武汉电信主站：`119.97.185.34:7709`
* 招商证券行情站：`119.147.164.60:7709`
* 华泰证券行情站：`221.236.86.140:7709`

*(注：服务端建议维护主站测速与心跳保活池，动态选择延时低于 30ms 的服务器)*

### 4.3 核心方法与数据能力契约（基于 pytdx API）
1. **`get_security_quotes([(market, code), ...])`**
   * 功能：批量拉取实时买卖五档、最新价、成交量、盘口快照。
   * 单批次容量：一次可传 **80 个标的**，返回耗时通常在 20ms~50ms 内。
2. **`get_history_minute_time_data(market, code, date)`**
   * 功能：获取指定历史日期的**完整 240 分钟分时行情**。
3. **`get_security_bars(category, market, code, start, count)`**
   * 功能：获取 K 线柱。
   * `category` 对应：`0`: 5分K, `1`: 15分K, `2`: 30分K, `3`: 60分K, `4`: 日K, `5`: 周K, `6`: 月K, `7`: 1分K。
4. **`get_transaction_data(market, code, start, count)`**
   * 功能：获取当日逐笔成交明细（分笔数据，每批最大 2000 笔），可用于精确回溯 **09:25 开盘集合竞价第一笔大单撮合**。

## 5. 数据源四：新浪财经与雪球数据源评估

### 5.1 新浪财经 (hq.sinajs.cn)
* **Endpoint**: `https://hq.sinajs.cn/list=sh600519,sz000001`
* **限制与防盗链（关键坑点）**：
  * **必须携带请求头**：`Referer: https://finance.sina.com.cn`
  * 编码：GBK
  * 频控：目前新浪针对公网 IP 限制较严，超过 15 QPS 容易遭遇 HTTP 403 阻断。
* **评估结论**：仅推荐作为多级故障切换的备用快照源。

### 5.2 雪球网 (stock.xueqiu.com)
* **Endpoint**:
  * 实时行情：`https://stock.xueqiu.com/v5/stock/quote.json?symbol=SH600519&extend=detail`

* **限制与防盗链（关键坑点）**：

* **评估结论**：数据结构规范，指标全面，但因强绑定 Session Cookie，不建议作为一级实时流数据源。

## 6. 集合竞价与盘后固定价格交易获取专项方案

A 股特殊交易时段是搭建高性能专业终端的关键差异化数据，具体规则与接入技术如下：

### 6.1 集合竞价时段数据获取 (09:15 - 09:25 & 14:57 - 15:00)

#### 交易规则特征：
* **09:15 ~ 09:20**：可以申报，也可以撤销申报（存在主力试盘与虚假申报）。
* **09:20 ~ 09:25**：只能申报，**不可撤单**（真实反映开盘意向）。
* **09:25**：交易所主机撮合成交，产生开盘价、集合竞价成交量、成交金额。
* **14:57 ~ 15:00**：深交所及上交所收盘集合竞价，**不可撤单**，15:00 撮合成交产生收盘价。

#### 接口获取技术路径：
1. **实时撮合快照轮询 (东方财富/腾讯)**:
   * 在 09:15:00 ~ 09:25:00 期间，以 3 秒为周期请求东方财富 `push2.eastmoney.com/api/qt/stock/get`。
   * 关注盘口买一卖一：当出现**匹配价格**时，买一和卖一价格相等，其挂单量分别代表**已匹配量**与**未匹配量**（买方未匹配或卖方未匹配）。
2. **通达信分笔成交反推 (逐笔明细)**:
   * 请求 `get_transaction_data(market, code, 0, 10)`，在 09:25:00 生成的第一笔分笔成交记录，即为**早盘集合竞价总撮合成交量与开盘价**。
   * 在 15:00:00 最后一笔成交记录即为**尾盘集合竞价撮合量**。

---

### 6.2 科创板与创业板“盘后固定价格交易”数据获取 (15:05 - 15:30)

#### 交易规则特征：
* **适用范围**：上交所科创板 (688xxx)、深交所创业板 (300xxx)。
* **交易时间**：交易日 15:05 ~ 15:30。
* **价格规则**：严格以**当日收盘价**进行逐笔申报，时间优先撮合。

#### 接口字段专属映射：
通过东方财富实时接口 `https://push2.eastmoney.com/api/qt/stock/get?secid={secid}&fields=f260,f261,f262,f263,f264` 直接提取：
* `f260`: 盘后固定价格成交量 (股)
* `f261`: 盘后固定价格成交额 (元)
* `f262`: 盘后固定价格成交笔数
* `f263`: 盘后未成交买入挂单量
* `f264`: 盘后未成交卖出挂单量

> **重要提示**：在常规日 K 线和标准交易时间（9:30~15:00）的分时图中，盘后固定价格交易**不计入**分时均价线和标准收盘价，必须在仪表盘中设计单独的“盘后交易”标签或辅助量柱展示。

## 7. 场内ETF与场外公募基金接入规范

### 7.1 场内交易型基金 (ETF / LOF)
场内 ETF（如华泰柏瑞沪深300ETF `510300`、易方达创业板ETF `159915`）在二级市场交易机制上与普通 A 股**完全一致**。
* **代码规则**：
  * 上交所 ETF：代码通常为 `51xxxx`、`58xxxx`（科创ETF），市场标识为 `sh` 或 `1.`
  * 深交所 ETF：代码通常为 `15xxxx`、`16xxxx`（LOF），市场标识为 `sz` 或 `0.`
* **实时估值 (IOPV)**：
  * 东方财富和腾讯行情快照中的即时价格即为**二级市场交易价**。
  * IOPV（基金份额参考净值）：通常在东财快照字段的特定净值字段（通常在 `f172` 或通过专门的基金净值接口下发）。

### 7.2 场外公募基金 (天天基金网接口)
场外公募基金（如易方达蓝筹精选 `005827`）非日内连续竞价，工作日每日 18:00~22:00 公布一次单位净值。

#### 盘中实时估值接口:
* **Endpoint**: `https://fundgz.1234567.com.cn/js/{fund_code}.js`
* **Method**: `GET`
* **示例**: `https://fundgz.1234567.com.cn/js/005827.js?rt=1600000000000`
* **返回格式 (JSONP)**:
  ```javascript
  jsonpgz({
    "fundcode": "005827",
    "name": "易方达蓝筹精选混合",
    "jzrq": "2026-09-24",      // 上一交易日净值日期
    "dwjz": "1.8540",          // 上一交易日单位净值
    "gsz": "1.8625",           // 盘中实时估算净值
    "gszzl": "0.46",           // 实时估算涨跌幅 (%)
    "gztime": "2026-09-25 14:45" // 估算时间
  });
  ```

#### 历史净值走势接口:
* **Endpoint**: `https://api.fund.eastmoney.com/f10/lsjz`
* **Query 参数**: `fundCode=005827&pageIndex=1&pageSize=30`
* **Header 关键要求**: `Referer: https://fundf10.eastmoney.com/` (必须携带，否则返回非法请求)。

## 8. 实时行情推送技术评估（WebSocket / SSE / 服务端中继广播）

### 8.1 免费源的原生推送现状与局限

| 推送模式 | 服务端可行性 | 协议规范 | 局限性与风险 |
| :--- | :--- | :--- | :--- |
| **东财 Server-Sent Events (SSE)** | ✅ 可行 | `https://push2.eastmoney.com/api/qt/stock/sse?secid={secid}&fields=...` | 建立长连接后，东财服务器主动推流（约每 2~3 秒推送一次增量 JSON）。**局限**：一个连接只能监听少量标的，无法单连接同时订阅上百只股票；外部长连接容易被云厂商反爬组件掐断。 |
| **机构 EMT / Level-2 WebSocket** | ❌ 免费不可用 | `wss://...` | 真正的低延时全量 WebSocket 推送属于券商/东财的机构付费 EMT/Choice 量化业务，免费公开端并未开放通用的 WSS 订阅入口。 |
| **通达信 Socket 直连** | ✅ 极佳 (准实时) | 客户端维护 TCP 长连接，内部定时发送查询心跳帧 | 属于 Pull 模型，但由于网络开销在几十毫秒级，可模拟出相当于 1~2 秒推送的准实时效果。 |

### 8.2 生产级架构结论：严禁前端直连外部金融接口
1. **IP 极易被拉黑**：若前端网页每个用户都直接向东财或腾讯发起 HTTP/SSE 请求，用户并发一旦上升，同源 Referer 或集中流量会瞬间导致接口被 403 封锁。
2. **跨域与防盗链限制**：新浪、东财历史接口要求特定 `Referer`，前端跨域无法自由覆写这些 Forbidden Header。
3. **推荐的最佳工程实践 ——「服务端中继分发架构」**：
   * **采集层（Ingestion Worker）**：由服务端集群负责以控制在安全阈值（5~10 QPS）内的频度，使用**腾讯批量接口 (`qt.gtimg.cn/q=...`) + 东方财富 K 线/盘后接口**，或通过 **pytdx TCP** 聚合拉取。
   * **缓存层（Cache Engine）**：写入内存（Redis / Local In-Memory Buffer）。
   * **推送层（Push Gateway）**：由自己的 Node.js/Go 服务端向前端建立 **WebSocket / Socket.io** 或 **SSE** 连接，实现面向前端可视化仪表盘的 100% 可控、低延迟推流。

## 9. 服务端高性能缓存与可视化仪表盘下发架构设计建议

为构建高性能金融数据可视化仪表盘，建议后端采用分层存储和计算架构：

```text
+-----------------------------------------------------------------------------------+
|                        外部公共数据源 (上游 Ingestion)                            |
|  [腾讯 qt.gtimg 批量快照]   [东财 push2his 历史K/分时]   [通达信 TCP:7709 毫秒底座]  |
+----------------------------------------+------------------------------------------+
                                         | HTTP / TCP Worker (定频/并发限制)
                                         v
+-----------------------------------------------------------------------------------+
|                     Node.js / Express 核心后端与时序缓存层                         |
|                                                                                   |
|  +------------------------+  +-------------------------+  +--------------------+  |
|  |   Redis / 内存快照     |  |   分时与K线时序环形缓冲  |  |    任务调度引擎    |  |
|  | (Snapshots: HSET/Hash) |  |   (RingBuffer / Redis)  |  | (Cron / Interval)  |  |
|  +------------------------+  +-------------------------+  +--------------------+  |
+----------------------------------------+------------------------------------------+
                                         | WebSocket 广播 / REST API 聚合接口
                                         v
+-----------------------------------------------------------------------------------+
|                     前端高性能金融可视化仪表盘 (Client App)                       |
|   [TradingView Lightweight Charts / ECharts K线]   [分时成交量/量比仪表盘]        |
+-----------------------------------------------------------------------------------+
```

### 9.1 数据存储与缓存设计模型
1. **当日分时时序数据 (1-minute Intraday)**:
   * **结构**：Redis `ZSET` 或内存定长浮点数组 `Float64Array`。
   * **格式**：每个标的存储当日 242 个点，时间为 Score，价格、成交量、均价打包为 Value。
   * **更新逻辑**：服务端每 2~3 秒获取一次快照，若当前分钟未结束，更新当前分钟 bar 的收盘价和累计成交量；进入下一分钟时追加新数据点。
2. **历史多周期 K 线 (Daily / 5-min K-line)**:
   * **结构**：持久化到磁盘缓存文件或数据库，冷启动时只读本地。
   * **更新逻辑**：非交易时段（每日 15:30 以后）触发定时任务，全量抓取前复权日 K 线；盘中只需将当日实时快照动态拼接为最后一根尚未收盘的“动态 K 线 Bar”。
3. **盘口与集合竞价 / 盘后交易字段**:
   * **结构**：Redis `HASH`，存储格式：  
     `stock:quote:{code} -> { price, preClose, open, high, low, volume, amount, callAuctionVol, afterHoursVol, ask1..5, bid1..5, updatedAt }`

### 9.2 前端可视化组件技术适配指南
* **推荐渲染引擎**：
  * **TradingView Lightweight Charts (轻量级首选)**：针对高频分时与 K 线渲染进行了极致 Canvas 优化，单页面流畅处理万级数据点，支持前复权坐标系平滑缩放。
  * **Apache ECharts**：适合展示分时图下方成交量 Bar、集合竞价多空对比柱状图、资金流向饼图。
* **数据传输协议**：
  * **初始页面加载**：HTTP `GET /api/kline?code=sh600519&type=day`（读取服务端本地缓存，响应时间 < 20ms）。
  * **盘中动态刷新**：WebSocket 通道发送增量 Patch：
    `{ type: "TICK", code: "sh600519", price: 1802.5, vol: 1540, time: 1727247000 }`，前端图表组件只调用 `series.update()` 刷新最后一根烛线或分时点，避免全量图表重绘。

## 10. 评估总结与接入实施路线图

1. **第一优先级（快照拉取）**：采用 **腾讯财经 `qt.gtimg.cn/q=...`**。一次请求拼接全市场重点自选池（100~200 只标的），2~3秒轮询一次，带宽消耗极小，零反爬风险。
2. **第二优先级（分时与历史K线）**：采用 **东方财富 `push2his.eastmoney.com/api/qt/stock/kline/get`**。按需拉取前复权 K 线，配合本地持久化存储。
3. **第三优先级（集合竞价与盘后交易）**：
   * 09:15~09:25 与 14:57~15:00 提取东财买一卖一及腾讯五档未匹配申报。
   * 15:05~15:30 读取东财 `f260~f264` 提取科创板/创业板盘后固定价格交易。
4. **第四优先级（长连接极速通道）**：在需要突破 HTTP 频控上限时，引入 **通达信 TCP Socket 协议** 作为底层采集器底座。
