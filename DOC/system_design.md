# A股实时与历史行情全栈系统设计方案 (Google AI Studio 运行环境)

## 1. 项目背景与目标

本项目计划在 **Google AI Studio (Web 全栈环境)** 中构建一个**高可用、低延迟、抗封控**的 A股/ETF/基金金融数据可视化仪表盘应用。

### 核心任务分解：
1. **动态股票池管理与持久化 (Dynamic Stock Pool Management)**：
   - 以 `/DOC/stockpool.json` 作为系统初始股票池种子数据（包含 66 只精选标的，涵盖军工、半导体、机器人、算力、高股息红利、科创50ETF等核心赛道，并内置行业分类、细分方向、关注等级、投资逻辑与风险说明）。
   - **用户端支持动态增删改**：前端用户可以在界面上自由添加新股票/基金、删除已有标的、调整观察层级（重点观察/候补观察/备选观察）。
   - **服务端同步保存与热更新**：服务端持久化保存最新的股票池列表，当股票池发生增删变更时，自动触发动态热加载与缓存温热。
2. **服务端数据采集与中继 (Ingestion Worker)**：
   - 利用已调研的免费数据源（腾讯财经批量快照、东方财富历史分时与复权 K 线、科创/创业板盘后交易字段），通过后台定时任务针对当前活跃股票池进行批量、定频、合规拉取。
3. **服务端多级缓存与时序引擎 (Server Cache Engine)**：
   - 在 Node.js 服务端维护内存级时序环形缓冲区 (Ring Buffer) 与持久化存储，屏蔽外部接口网络抖动与频控风险，对外提供毫秒级响应的 REST API。
4. **交易时段状态机 (Market Session State Machine)**：
   - 自动识别开盘集合竞价 (09:15-09:25)、连续竞价 (09:30-11:30, 13:00-15:00)、午间休盘 (11:30-13:00)、尾盘竞价 (14:57-15:00)、盘后固定价格交易 (15:05-15:30) 与非交易时段，智能动态调整采集频率，防止非交易时间浪费资源及交易时间漏采。
5. **浏览器前端实时同步与高性能图表 (Real-time Sync & Visualization)**：
   - 利用 **SSE (Server-Sent Events)** 将实时 Tick、分时分钟 Bar 增量下发至前端。前端基于 Canvas 渲染引擎（如 TradingView Lightweight Charts 和 Apache ECharts）呈现毫秒级平滑分时、多周期 K 线、买卖五档盘口与投资逻辑看板。

## 2. 动态股票池与元数据架构设计

### 2.1 股票池数据结构规范 (`stockpool.json`)

系统股票池数据模型定义如下：

```typescript
export interface StockPoolItem {
  seq: string;        // 序号 (如 "1")
  ind: string;        // 申万/自定义行业 (如 "军工", "半导体", "计算机", "基金/ETF")
  sub: string;        // 细分赛道 (如 "高温合金", "刻蚀设备", "机器人减速器", "宽基ETF")
  name: string;       // 证券名称 (如 "图南股份", "中芯国际", "科创50ETF华夏")
  code: string;       // 6位证券代码 (如 "300855", "688981", "588000")
  keyObs?: string;    // 重点观察标的标注
  candObs?: string;   // 候补观察标的标注
  altObs?: string;    // 备选观察标的标注
  tier: '重点观察' | '候补观察' | '备选观察'; // 观察层级
  logic: string;      // 核心投资逻辑与催化剂
  risk: string;       // 潜在风险与跟踪要点
  // --- 运行时动态衍生属性 (由服务端补充) ---
  marketPrefix?: 'sh' | 'sz' | 'bj'; // 腾讯/通用市场前缀
  secid?: string;                    // 东方财富 secid (如 "0.300855", "1.688981")
  createdAt?: number;                // 添加时间戳
}
```

### 2.2 证券代码与市场前缀自动推导引擎

用户在前端添加股票时仅需输入 **6位纯数字代码**（例如 `600519` 或 `300855` 或 `588000`），服务端引擎自动执行市场推导映射：

| 证券类型 | 6位代码前缀规律 | 交易所 | 腾讯代码前缀 (`symbol`) | 东方财富 `secid` |
| :--- | :--- | :--- | :--- | :--- |
| **沪市主板 A 股** | `600`, `601`, `603`, `605` | 上交所 (SH) | `sh60xxxx` | `1.60xxxx` |
| **科创板 A 股** | `688`, `689` | 上交所 (SH) | `sh688xxx` | `1.688xxx` |
| **深市主板 A 股** | `000`, `001`, `002`, `003` | 深交所 (SZ) | `sz00xxxx` | `0.00xxxx` |
| **创业板 A 股** | `300`, `301` | 深交所 (SZ) | `sz30xxxx` | `0.30xxxx` |
| **北交所 A 股** | `83`, `87`, `43`, `92` | 北交所 (BJ) | `bj83xxxx` | `0.83xxxx` |
| **上交所 ETF / LOF** | `51`, `58` (科创ETF) | 上交所 (SH) | `sh588000` | `1.588000` |
| **深交所 ETF / LOF** | `15`, `16` | 深交所 (SZ) | `sz159915` | `0.159915` |

### 2.3 股票池热更新生命周期与缓存联动

```text
[用户前端操作: 添加股票 601318 / 删除股票]
                   |
                   v
[POST /api/stockpool / DELETE /api/stockpool/:code]
                   |
                   +---> 1. 验证有效性: 调用腾讯单条快照检查代码是否存在及校验证券名称
                   |
                   +---> 2. 原子落盘: 更新服务端本地持久化文件 (`./data/stockpool.json`)
                   |
                   +---> 3. 热温热 (Hot Warming):
                   |        - 立即拉取该股票的历史日K与分时数据并写入缓存
                   |        - 动态注入到后台轮询 Batch 列表
                   |
                   +---> 4. SSE 广播通知前端:
                            下发 `event: pool_updated`，所有已打开仪表盘客户端静默同步最新列表
```

## 3. Google AI Studio 运行环境特征与技术适配

在 Google AI Studio 平台中，应用运行于托管的 Cloud Run 容器中，其特有的运行约束决定了系统架构的选型：

| 平台特征 | 架构约束与影响 | 针对性技术决策 |
| :--- | :--- | :--- |
| **单进程全栈容器** | 服务端通常由单个 Node.js 进程托管 Express + Vite | 采用 `server.ts` 模式：Express 暴露 `/api/*` 路由并挂载 Vite 静态资源中间件，Ingestion Worker 作为后台 Interval 任务常驻同一进程。 |
| **容器内存与磁盘特性** | 容器分配充足内存（通常 1~2GB+），本地文件系统为容器内挂载盘 | **动态股票池与缓存策略**：种子股票池读取 `/DOC/stockpool.json`，用户修改持久化至 `./data/stockpool.json`。实时行情保存在 Node.js 内存堆 (`Map`)，历史 K 线写入本地 JSON 缓存文件。 |
| **外部网络访问** | 服务端 outbound 自由发起 HTTPS/HTTP 请求，不受浏览器 CORS 限制 | **彻底解决防盗链与跨域**：所有针对腾讯、东财、新浪的请求均由 Node.js 发起，可随意伪造 `Referer: https://finance.sina.com.cn` 或特定 Header，避免前端直接暴露。 |
| **iFrame 运行前端** | 浏览器端页面嵌入在 AI Studio iFrame 中 | **实时通信选型**：优先采用 **HTTP Server-Sent Events (SSE)**。SSE 在 iFrame 中具有更佳的防火墙穿透性与极简重连机制，协议轻量且天然单向。 |
| **HMR 已禁用** | 修改代码需通过重编译保证状态一致 | 模块化设计服务端代码，采集器、缓存层、路由层清晰解耦。 |

## 5. 服务端核心模块技术设计

### 5.1 动态股票池管理服务 (`StockPoolService`)

1. **初始种子数据自动装载**：
   - 服务端启动时，优先检测运行目录中的 `./data/stockpool.json` 是否存在；
   - 若不存在，自动将 `/DOC/stockpool.json` 中的 66 只精选标的作为默认种子数据写入 `./data/stockpool.json`，确保首次启动即可立即展示丰富数据。
2. **股票池存储接口契约**：
   - `GET /api/stockpool`：
     返回当前股票池全量列表（合并每个标的的最新行情快照：最新价、涨跌幅、成交额，支持按行业 `ind` 与层级 `tier` 过滤）。
   - `POST /api/stockpool`：
     - 请求体：`{ code: "601318", ind: "非银金融", sub: "保险", tier: "重点观察", logic: "...", risk: "..." }`
     - 动作：
       1. 校验 6 位代码，并自动推导市场代码（`sh` / `sz` / `1.` / `0.`）；
       2. 调用腾讯接口 `https://qt.gtimg.cn/q={symbol}` 获取该标的实时快照，自动补全股票官方名称 `name`；若外部接口返回空值，则拒绝添加并向前端返回“无效证券代码”；
       3. 追加写入 `./data/stockpool.json`；
       4. 触发历史数据异步预热（拉取日 K 线与当日分时）；
       5. 将该标的加入定时轮询数组。
   - `DELETE /api/stockpool/:code`：
     从股票池中移除指定代码，并从当前内存轮询列表中剔除。
   - `PUT /api/stockpool/:code`：
     更新指定股票的配置信息（如调整观察层级 `tier`、修改核心逻辑 `logic` 或风险提示 `risk`）。
   - `POST /api/stockpool/reset`：
     一键重置功能，将股票池还原为 `/DOC/stockpool.json` 的初始 66 只标的。

### 5.2 交易时段状态机 (Market Scheduler)
服务端通过精准到秒的状态机控制外部拉取频率，保证当前股票池全量数据的及时刷新，同时将外部 QPS 严格压制在安全范围内：

```text
时间轴 (北京时间 CST = UTC+8):
00:00                09:15    09:25    09:30        11:30        13:00        15:00    15:30   24:00
  |--------------------|--------|--------|------------|------------|------------|--------|------|
       夜间休眠         早盘竞价  撮合准备    连续竞价       午间休市      连续竞价    收盘竞价  盘后固定  休眠归档
      (60s轮询)          (3s)    (1s)      (2s)         (30s)         (2s)      (1s)     (5s)   (归档停机)
```

#### 腾讯超长批量拉取优化（抗封控核心保障）：
- 腾讯接口允许单次请求拼接 100~200 个标的。当前股票池包含 66 只股票，**仅需 1 个 HTTP 请求**即可获取整池全部标的的买卖五档、最新价、成交量、成交额：
  `https://qt.gtimg.cn/q=sz300855,sh601606,sz002008,sh688017,sh588000,...`
- 在连续竞价时段每 2 秒发起 1 次批量请求，外部 QPS 仅为 **0.5 QPS**，不仅耗时低于 100ms，而且彻底杜绝 IP 被封禁的风险。

### 5.3 服务端三级缓存体系

1. **实时最新快照缓存 (In-Memory Tick Map)**:
   - 内存字典存储当前股票池所有标的的完整盘口镜像：最新价、昨收、今开、最高、最低、成交量、买卖五档挂单、集合竞价匹配量与盘后固定价格交易字段。
2. **当日分时时序缓冲区 (Minute Ring Buffer)**:
   - 每个标的维护全天固定 242 根 1 分钟柱。服务端每秒将采集到的最新价计算归并到当前分钟的 Bar 中（开、高、低、收、累计成交量、均价），并更新时序环。
3. **历史多周期 K 线持久化缓存 (File-based LRU Cache)**:
   - 磁盘文件路径：`./cache/klines/{code}_{period}_{fq}.json`。
   - 包含 500 根前复权 K 线，盘中启动时优先直接读取本地文件，提供 $\le 5\text{ms}$ 的极致冷启动体验。

### 6.2 SSE 实时增量推流规范 (`/api/realtime/stream`)

* **Endpoint**: `GET /api/realtime/stream`
* **协议头**: `Content-Type: text/event-stream`, `Connection: keep-alive`
* **下发事件定义**:
  1. **`event: pool_updated`**：
     当用户在其他页面或窗口修改股票池时广播，客户端自动刷新列表。
  2. **`event: batch_tick`**：
     交易时段每 2 秒向前端广播整池简要行情增量包（代码、最新价、涨跌幅、现手、成交额），用于前端自选列表高频数字跳变与红绿闪烁。
  3. **`event: active_tick`**：
     针对当前用户正在激活查看的详情股票，下发完整的买卖五档、盘口深度、当日最高/最低与成交明细。
  4. **`event: minute_bar`**：
     每分钟结束时下发最新闭合的 1 分钟分时 Bar，用于图表无缝追加新点。

## 7. 前端可视化仪表盘设计

### 7.1 股票池多维赛道看板与操作设计
* **行业与赛道过滤栏**：
  提供快捷胶囊标签（全部、军工、半导体、机械设备/机器人、电子、计算机/算力、高股息/银行/电力、消费/白酒/免税、汽车/新能源、基金/ETF）。
* **观察层级切片**：
  一键筛选「重点观察 (20只核心)」、「候补观察 (13只弹性)」、「备选观察 (33只拓展)」。
* **股票池快捷操作**：
  - 点击右上角「**+ 添加标的**」：弹出模态框，输入股票代码时实时通过防抖接口检查名称（如输入 `600519` 自动识别为“贵州茅台”），支持自定义选择赛道、层级并填写备忘投资逻辑；
  - 列表行右侧提供「**移除**」操作二次确认气泡；
  - 标的卡片支持「**展开投资逻辑**」：在抽屉面板或卡片折叠区域清晰展示选股逻辑 (`logic`) 与风险警示 (`risk`)。

### 7.2 专业金融图表集成 (TradingView Lightweight Charts)
* **分时走势图**：
  - 面积渐变曲线展示即时成交价格；
  - 叠加计算即时成交均价线（黄色线）；
  - 下方同步联动成交量柱状图（红涨绿跌）；
  - 顶部显示昨收基准参考线，支持 09:15-09:25 早盘集合竞价多空匹配数据标记。
* **K 线走势图**：
  - 支持 **日K / 周K / 60分钟 / 15分钟 / 5分钟** 切换；
  - 支持 **前复权 (QFQ) / 不复权** 切换；
  - 自动叠加 MA5、MA10、MA20、MA60 均线组；
  - 支持十字光标悬浮显示 OHLCV 详情及换手率。
